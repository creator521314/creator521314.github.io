项目 02 · 中文输入

ibus-rime

在 GNOME Wayland 下，把 IBus 的中文引擎从 libpinyin 换成 Rime——不换输入法框架，只换引擎， 并配上一键切换脚本和零依赖的配置向导。

为什么换掉 libpinyin

不是配置问题，是词库的持久化机制不适配 Wayland 的会话生命周期。

  • 症状。选过的字下次还是排在后面，甚至一分钟内重复输入也不调整。
  • 证据。~/.cache/ibus/libpinyin/ 里 user.bin 只有文件头， user_bigram.db 只有签名、零词条，时间戳集中在几分钟内——是反复重建，不是累积。
  • 根因。libpinyin 在内存里训练，进程优雅退出时才落盘；GNOME Wayland 下 IBus 引擎跟着 gnome-shell 生死，注销/重启常被 SIGKILL，写盘函数没机会执行。

为什么留在 IBus

换引擎，不换框架。

  • ibus 是 gnome-shell 的硬依赖。 pacman -R ibus 会连带删掉整个 GNOME，所以只能换引擎。
  • fcitx5 在 GNOME Wayland 下要多绕一道。 GNOME 不支持 Wayland 的 input-method 协议，候选框定位要靠 kimpanel 扩展，还得改 IM 环境变量。
  • Rime 的差别在落盘时机。每次上屏即写 userdb，异常退出也不丢词频。

怎么配

Rime 没有图形设置界面，所有配置都在 YAML 里，改完要重新部署。

层内容
方案 只保留 luna_pinyin_simp（朙月拼音·简化字），隐藏注音、仓颉、地球拼音
候选 每页 7 个，横排显示
模糊音 zh-z / ch-c / sh-s、n-l、en-eng / in-ing、an-ang
词库 开启用户词库，选过的词按词频排序

配置片段

模糊音必须用 /+ 追加，不能整体替换。

patch:
  schema_list:
    - schema: luna_pinyin_simp
  menu/page_size: 7
  style/horizontal: true

# luna_pinyin_simp.custom.yaml
patch:
  "speller/algebra/+":
    - derive/^([zcs])h/$1/
    - derive/([ei])n$/$1ng/
    - derive/([ei])ng$/$1n/
  "translator/enable_user_dict": true

luna_pinyin 的 algebra 是 __patch: 地图而不是列表， 直接写 "speller/algebra": [...] 会让 YAML 解析失败；替换式写法还会丢掉方案自带的简拼和纠错。

用起来

切换脚本负责环境，配置向导负责偏好，部署后立即生效。

sudo pacman -S --needed ibus-rime librime-data
bash switch-ime-rime.sh        # 装包 + 注册输入源 + 备份旧词库
python3 rime-wizard.py         # 方案 / 候选数 / 模糊音 / 翻页键
ibus restart

首次使用按 Super+Space 切到「中文 (Rime)」，选朙月拼音，再右键托盘图标「部署」。 配置改完不会自动生效，也可以直接跑 rime_deployer --build。

踩过的坑

  • 设置里的齿轮点了没反应：rime.xml 没有 <setup> 字段，正常，改 YAML 后部署即可。
  • 候选全是繁体：用的是 luna_pinyin 而不是 luna_pinyin_simp。
  • 部署报 end of map not found：algebra 用了替换而不是 /+ 追加。
  • 用户词库不增长：部署没成功，确认 build/ 里有对应的 .schema.yaml。
